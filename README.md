# ジュンの野球ノート

野球の練習・試合で気づいたこと、目標、次の練習を記録し、招待した家族で共有するアプリです。

- アプリ: https://kickerdrops-bot.github.io/jun-baseball-note/
- ソース: https://github.com/kickerdrops-bot/jun-baseball-note

画面とソースは公開されます。記録は専用の Supabase に保存し、招待済みの家族だけが読み取れる構成です。メールアドレス、記録、設定リンク、サービス秘密鍵は、このリポジトリに保存しません。

## 家族の使い方

| 役割 | できること |
| --- | --- |
| writer（ジュン） | 記録の作成・編集・削除、目標と行動の達成チェック、バックアップ取り込み |
| viewer（家族） | 記録の閲覧 |
| manager（管理者） | 記録の閲覧、家族の招待・解除、パスワード再設定リンクの発行 |

管理者が家族画面でメールアドレスと役割を指定し、発行された設定リンクを本人に直接渡します。アプリからメールや LINE は自動送信しません。本人がリンクを開いて自分のパスワードを設定した後は、メールアドレスとパスワードでログインします。ジュン用の writer は 1 名です。管理者は自分を解除できません。

設定リンクには有効期限があり、使用済みのリンクは再使用できません。使えない場合は管理者が新しいリンクを発行します。リンクはパスワードと同じように扱い、公開ページ・GitHub Issue・共有ログへ貼り付けないでください。

## 保存と更新

Supabase 上の記録が正本です。画面を開いた時、画面へ戻った時、更新ボタンを押した時に最新の記録を取得します。別の端末での変更を見たい時は更新してください。

保存にはインターネット接続が必要です。保存エラー時は入力を残し、保存完了として扱いません。同じ記録を複数画面で変更すると更新番号の競合を検出します。最新の記録を確認してから保存し直してください。保存中や入力中は画面を閉じず、保存完了を確認してください。

家族の解除後は、その利用者の既存ログインが残っていても次のデータ取得や保存は拒否されます。すでに閲覧・ダウンロード済みの内容を相手の端末から消すことはできません。

## 旧ノートからの移行とバックアップ

旧 localhost 版の記録は端末・ブラウザ内にあるため、新しい URL には自動移行されません。

1. 旧ノートを記録していた同じブラウザで開き、JSON バックアップを書き出します。
2. 新しいアプリに writer としてログインします。
3. JSON 取り込みを選び、追加件数を確認して実行します。
4. 内容と件数を確認したら、新しいバックアップも保存します。

取り込みは追加方式です。同じ ID の記録や内容が重複する記録をスキップし、既存記録を上書きしません。不正な形式や制限を超えたファイルは取り込みません。viewer と manager は取り込めません。

バックアップには記録本文が含まれます。家族だけがアクセスできる場所へ保存し、この公開リポジトリには追加しないでください。JSON は記録のバックアップであり、ログイン情報・家族の所属・Supabase 全体を復元するものではありません。

## 開発と GitHub Pages

Node.js 24 と、`package.json` に固定された pnpm を使います。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm build
pnpm preview
```

開発サーバーは `pnpm dev`、ポート 5178。ビルドのプレビューはポート 4178 です。URL はどちらも `/jun-baseball-note/` を付けます。既存の別アプリ用サーバーを停止する必要はありません。

`vite.config.js` の `base` は `/jun-baseball-note/` です。`main` への push で GitHub Actions がテスト・ビルド・Pages 公開を実行します。GitHub の Settings → Pages → Source は GitHub Actions を選びます。公開されるのはビルド済み `dist` だけです。

`cloud.js` に置くのは Supabase URL とブラウザ公開用キーだけです。service role / secret キーを `VITE_` 変数やフロントエンドに追加しないでください。秘密鍵は Edge Functions または管理用の非公開環境に限定します。`.env*`、`private/`、バックアップ、旧 Sites の管理情報は Git の対象外です。

Supabase の構築、管理者の初期設定・復旧、家族管理 API の運用は [バックエンド運用手順](supabase/OPERATIONS.md) を参照してください。

依存関係は正確なバージョンで固定し、`pnpm-lock.yaml` をコミットします。CI はロックファイルを書き換えません。更新時は Supabase の変更履歴、依存関係の差分、認証・権限・バックアップの検証結果を確認します。

## 無料 Supabase の一時停止と復旧

無料プランは低利用の状態が 7 日間続くと一時停止されることがあります。停止中はログイン・取得・保存ができません。画面の入力を別途控え、書き込みに成功したと判断しないでください。[公式の稼働条件](https://supabase.com/docs/guides/deployment/going-into-prod)

1. Supabase の管理アカウントで Dashboard にログインします。
2. このアプリ専用のプロジェクトを選び、停止中の場合は Restore / Resume を実行します。他事業のプロジェクトは操作しません。
3. 復旧完了を待ち、アプリでログイン・記録の取得を確認します。
4. writer で保存し、別の viewer で更新後に見えることを確認します。検証記録は削除します。

長期間停止して復元方法が変わっている場合は、Dashboard の案内と [Project Pausing の公式手順](https://supabase.com/docs/guides/platform/free-project-pausing) を確認します。現在の公式手順では、停止から 1 年以内が Dashboard での復元期間です。費用のかかるプラン・機能へ自動変更する運用はありません。

無料プランでは定期的に手元へバックアップを保存してください。アプリの JSON 書き出しに加え、運用担当者は必要に応じて Supabase CLI による DB バックアップを管理します。DB バックアップには家族情報が含まれるため非公開に保管します。[公式バックアップ手順](https://supabase.com/docs/guides/platform/backups)

## 公開前・変更後の確認

- 未ログイン、未招待、解除済みの利用者が記録を取得できないこと。
- viewer / manager が API を直接呼び出しても記録を書けず、writer が家族管理 API を使えないこと。
- 自分の metadata を変更しても役割や所属を昇格できないこと。
- writer の保存が別端末の viewer に反映されること。
- 招待・再設定、期限切れ・使用済みリンク、ログアウトを確認すること。
- 保存失敗と同時編集で入力が失われず、無言の上書きがないこと。
- 旧 JSON の取り込み、重複、不正ファイル、バックアップ復元を確認すること。
- スマートフォンと PC の表示、公開 URL のアセット、認証 callback、HTTPS、Actions の成功を確認すること。
- Supabase の Security / Performance Advisor を確認すること。

`pnpm test` はバックアップの妥当性・重複処理と、取得・保存・取り込み確認の競合を検証します。ブラウザ操作、実際の認証、RLS の実機検証は別途必要です。
